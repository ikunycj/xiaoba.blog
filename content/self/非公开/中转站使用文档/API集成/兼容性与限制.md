# 接口选择与兼容性

## 先做这一步

```bash
curl https://alltokenapi.com/v1/models \
  -H "Authorization: Bearer sk-your-api-key"
```

只使用返回的模型 ID。模型必须支持你准备调用的接口；能聊天不代表能生成图片、向量、音频或视频。

## 怎么选接口

| 需求                         | 接口               |
| -------------------------- | ---------------- |
| 普通文字聊天                     | Chat Completions |
| 推理、工具调用、Codex              | Responses        |
| Claude Code                | Claude Messages  |
| Gemini CLI 或 Gemini 原生 SDK | Gemini 原生接口      |
| 旧版文本续写                     | Completions      |
| 图片生成或编辑                    | Images           |
| 异步视频                       | Videos           |

OpenAI 格式的模型列表会返回 `supported_endpoint_types`。优先选择同时出现在模型列表和请求路径中的能力；不要仅凭模型名称猜测接口支持情况。

## 官方参数文档

本站只说明本站地址和最小请求，完整参数以官方文档为准：

| 协议 | 官方文档 |
| --- | --- |
| Chat | [OpenAI Chat](https://platform.openai.com/docs/api-reference/chat) |
| Responses | [OpenAI Responses](https://platform.openai.com/docs/api-reference/responses) |
| Claude | [Anthropic Messages](https://docs.anthropic.com/en/api/messages) |

| 视频 | [OpenAI Videos](https://platform.openai.com/docs/api-reference/videos) |

## 协议不要混用

- Chat 请求体不能直接发送到 Responses、Claude 或 Gemini 路径。
- Claude Code 使用服务根地址；OpenAI SDK 通常使用带 `/v1` 的地址。
- 图片编辑、音频转写、音频翻译和视频创建使用 `multipart/form-data`。
- Realtime 使用 WebSocket。
- `/v1/responses/compact` 只用于明确支持该端点的 OpenAI/Codex 模型。
- `/v1/edits` 当前按图片编辑处理。

## 专用任务路径

以下任务接口统一使用 `Authorization: Bearer sk-your-api-key`，请求体按对应服务格式填写：

| 服务 | 路径 |
| --- | --- |
| Kling 文生视频 | `POST /kling/v1/videos/text2video` |
| Kling 图生视频 | `POST /kling/v1/videos/image2video` |
| Midjourney | `POST /mj/submit/{action}` |
| Suno | `POST /suno/submit/{action}` |
| 即梦 | `POST /jimeng/` |

这些接口使用对应服务商的请求格式，不要发送 OpenAI Chat 请求体。

## 常见错误

| 错误 | 先检查 |
| --- | --- |
| `401` | API Key、请求头、Base URL |
| `400` | 模型 ID、路径、必填字段、请求体格式 |
| `404` | 是否重复或遗漏 `/v1`，模型或任务 ID 是否正确 |
| `403` | API Key 的模型、IP、分组权限 |
| `429` | 余额、额度、速率限制和上游负载 |

收到 `200` 但业务结果失败时，继续查看响应体中的 `error` 或任务状态；异步视频、Kling、Midjourney、Suno 和即梦需要先提交任务，再轮询任务结果。
