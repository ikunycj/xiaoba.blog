# 文本补全

传统 Completions 接口根据一段提示词续写文本。新项目通常优先使用 Chat Completions 或 Responses API，只有旧 SDK、旧模型或特定工作流需要使用本接口。

## 请求

```http
POST /v1/completions
```

```bash
curl "https://alltokenapi.com/v1/completions" \
  -H "Authorization: Bearer sk-your-api-key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "your-completion-model-id",
    "prompt": "The most important property of a reliable API is",
    "max_tokens": 64,
    "temperature": 0.7
  }'
```

## 请求字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `model` | string | 是 | 支持传统 Completions 端点的模型 ID |
| `prompt` | string/array | 是 | 需要续写的提示词 |
| `max_tokens` | integer | 否 | 最大生成 Token 数 |
| `temperature` | number | 否 | 采样温度 |
| `top_p` | number | 否 | 核采样参数 |
| `n` | integer | 否 | 返回的候选数量，使用前确认模型限制和计费影响 |
| `stream` | boolean | 否 | 是否流式返回结果 |
| `stop` | string/array | 否 | 停止序列 |
| `echo` | boolean | 否 | 是否在响应中回显输入 |
| `suffix` | string | 否 | 部分补全模型支持的后缀 |

## 响应示例

```json
{
  "id": "cmpl_xxx",
  "object": "text_completion",
  "created": 1760000000,
  "model": "your-completion-model-id",
  "choices": [
    {
      "index": 0,
      "text": " predictable behavior under failure.",
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 10,
    "completion_tokens": 6,
    "total_tokens": 16
  }
}
```

## 兼容性说明

- 不是所有聊天模型都支持 `/v1/completions`。
- 模型出现在 `/v1/models` 中，不代表一定支持传统补全端点。
- 新模型通常对 `/v1/chat/completions` 或 `/v1/responses` 支持更完整。

## 常见问题

- `messages is required`：当前模型或客户端实际走的是 Chat Completions，请改用 `/v1/chat/completions`。
- 模型不可用：在定价页面按端点类型筛选支持传统补全的模型。
- 返回格式不符合预期：确认 SDK 使用的是 Completions 响应类型，而不是 Chat Completions 类型。
