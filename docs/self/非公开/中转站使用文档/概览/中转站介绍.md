# 中转站介绍

## 什么是中转站

AI 中转站是连接用户与模型服务商的统一 API 网关。应用、脚本或 AI 编程工具先把请求发送到中转站，中转站完成身份验证、模型匹配和渠道路由后，再把请求转发给对应的上游模型，并将结果返回给用户。

```text
客户端或应用 -> All Token API -> 可用的上游渠道 -> AI 模型
```

中转站本身不是 AI 模型，也不会改变客户端的主要使用方式。通常只需要准备以下三项信息，即可接入兼容的客户端：

- **API Key**：用于验证身份和记录用量。
- **Base URL**：本站的统一服务地址。
- **模型 ID**：用于指定实际调用的模型。

本站同时提供 API Key 管理、模型权限、余额与计费、使用日志等配套功能，方便在一个控制台中完成日常使用和排查。

## 为什么会有中转站

不同模型服务商的账号体系、服务地址、接口协议和计费方式并不完全一致。直接接入多个服务商时，用户往往需要分别注册账号、管理密钥、维护配置，并自行处理模型切换和接口差异。

中转站主要解决以下问题：

- **统一入口**：通过一个站点管理多个模型，不必为每个模型重复维护一套连接信息。
- **降低接入成本**：兼容常见 API 协议和客户端，通常只需更换 API Key、Base URL 和模型 ID。
- **简化模型切换**：在同一套接入方式下选择不同模型，减少客户端配置变更。
- **集中管理用量**：统一查看余额、请求记录、Token 用量和实际费用。
- **提高渠道灵活性**：根据模型、分组和可用渠道完成请求路由，减少对单一上游入口的依赖。

中转站统一的是接入和管理方式，不代表所有模型都支持相同的协议或能力。使用前仍需在模型定价页面确认模型 ID、端点类型、价格和限制。

## 本中转站特色与优势

### 多模型统一接入

本站聚合多种常用 AI 模型，可在模型定价页面查询当前可用模型。一个 API Key 只会看到其权限和路由配置范围内的模型，便于按不同应用划分访问范围。

### 支持多种 API 协议

除常见的 OpenAI Chat Completions 外，本站还提供以下协议入口：

- OpenAI Responses API
- Anthropic Messages API
- Gemini `generateContent` API
- Embeddings API

模型名称相似并不代表支持相同协议。实际调用时，应以定价页面显示的端点类型为准。

### 丰富的客户端接入文档

本站提供 CC Switch、Codex、Claude Code、Gemini CLI、OpenCode、OpenClaw 和 Hermes 等工具的配置指南。CC Switch 支持从 API Key 页面一键导入 Claude、Codex 和 Gemini 配置，减少手动填写错误。

### 清晰的模型定价与用量记录

模型定价页面会展示模型的计费方式、输入与输出价格、可用分组以及已配置的动态定价规则。请求完成后，可在使用日志中核对模型、端点、Token 数、分组和最终费用。

### 灵活的 API Key 管理

创建 API Key 时，可根据使用场景设置有效期、额度、模型限制和 IP 限制。建议为不同设备、应用或项目分别创建密钥，避免共用一个长期、无限制的密钥。

### 多渠道路由与可用性管理

本站可根据模型和 API Key 的分组配置选择可用渠道，并结合渠道状态完成请求路由。该能力可以减少手动切换渠道的工作，但上游服务异常、模型限流或网络波动仍可能导致请求失败。

## 开始使用

1. [打开钱包](https://alltokenapi.com/wallet)，确认余额或订阅额度可用。
2. [查看模型定价](https://alltokenapi.com/pricing)，选择模型并确认支持的端点类型。
3. [创建 API Key](https://alltokenapi.com/keys)，按使用场景设置权限和限制。
4. 阅读 [API 集成指南](../API集成/API集成指南.md) 或对应的工具接入文档。

> 请妥善保存 API Key，不要将其写入公开代码、截图、聊天记录或浏览器前端代码中。如果密钥可能已经泄露，请立即撤销并重新创建。
